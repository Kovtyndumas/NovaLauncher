Nova Launcher — сборка

Откройте терминал в этой папке (рядом с package.json).

1. Установите Node.js LTS.
2. Установите зависимости: npm ci
3. Запустите проверки: npm test
4. Запустите приложение: npm start

Установщики (собирать на соответствующей системе):

macOS Intel и Apple Silicon: npm run dist:mac
Windows x64: npm run dist:win
Linux x64 (AppImage): npm run dist:linux

Готовые файлы появятся в dist. Зависимости для другой ОС устанавливайте заново через npm ci, не переносите node_modules между компьютерами.

На macOS без сертификата выполняется полная ad hoc-подпись приложения и вложенных компонентов. Developer ID и notarization macOS / подпись Windows отдельно не настроены. При наличии подходящего сертификата electron-builder может использовать его автоматически.

В установщик входят код приложения, production-зависимости, шрифты и локальная библиотека персонажа. Тесты, старый HTML, игровые миры, пользовательские аккаунты и локальные инстансы в него не входят.

Новые возможности

• Все официальные релизы Minecraft начиная с 1.0 доступны в создании инстанса и фильтре контента. Каталог Mojang сохраняется для следующего запуска без сети. Наличие загрузчика проверяется отдельно при установке: Fabric/Forge и другие поддерживают не каждую версию. Для старых версий на Apple Silicon используется Java x64; нужна Rosetta 2. Запуск всех исторических версий на всех ОС не гарантируется.
• На экране «Играть»: «Копия» создаёт отдельный инстанс с мирами и модами, «Миры» создаёт и восстанавливает резервные копии. Старые копии и логи не дублируются. Перед обновлением модов/контента миры сохраняются автоматически. Резервные копии лежат внутри инстанса в backups/worlds; для защиты от потери диска храните отдельную копию на другом носителе.
• В «Контенте» установленные ресурспаки и шейдеры можно включать, удалять и обновлять. Включение применяется при следующем запуске. Для шейдеров нужен Iris или OptiFine. Перед заменой/удалением файлы сохраняются в backups/content. Обновление доступно для файлов, установленных через каталог Modrinth.
• «История» в боковой панели показывает время и последние запуски с быстрым повторным запуском. Отдельные закрытые сеансы сохраняются в play-history.json.

Minecraft 26.3 RUST (Horizon)

В «Новый инстанс» выберите версию «26.3 RUST». Nova сохранит числовую версию Minecraft 26.3 и отдельный движок Rust, скачает официальный переносимый Horizon Launcher при установке/первом запуске и проверит размер и SHA-256 по метаданным GitHub Releases. Уже установленный движок повторно не скачивается.

Закреплены Horizon v0.2.97 и Horizon Launcher launcher@0.2.54. В research-lock.json этого релиза указана Minecraft 26.3:
https://github.com/horizon-rust/horizon/blob/v0.2.97/research-lock.json

Кнопка «Установить 26.3 RUST» ставит движок. Кнопка «Войти в Horizon» открывает официальный Horizon в контексте именно этого инстанса. Войдите в Microsoft с приобретённой Java Edition и закройте окно Horizon. Обычная кнопка «Играть» затем подготовит ресурсы из Mojang и запустит игру. Команды prepare и play всегда получают --version v0.2.97; выбор другой версии в интерфейсе Horizon не меняет закреплённую версию Nova.

В эту сборку входят нативные клиенты для macOS Apple Silicon, Windows x64 и Linux x64. На macOS Intel и Linux ARM64 Nova покажет сообщение о неподдерживаемой платформе для закреплённой сборки. Клиент Horizon требует собственного входа; вход Microsoft в Java-части Nova автоматически ему не передаётся. Без входа движок можно установить, но подготовить ресурсы и играть нельзя.

Миры находятся в обычной папке инстанса Nova; метаданные, скачанные сборки и вход Horizon — в userData / horizon-instances / ID инстанса. Переносимый лаунчер — в userData / runtimes / horizon-launcher. Существующие Java-инстансы и отдельная установка Horizon не изменяются. Копирование инстанса переносит миры, но вход Horizon в копии выполняется отдельно. Java-моды и Java-шейдеры через каталог Nova в Rust-инстанс не устанавливаются: используйте форматы и управление контентом Horizon.

Документация команд: https://playhorizon.dev/docs/api/launcher

Обновления Nova через GitHub

Источник по умолчанию: Releases репозитория https://github.com/Kovtyndumas/NovaLauncher
Автоматическая проверка при запуске установленной Nova и каждые 4 часа; загрузку и перезапуск подтверждает пользователь кнопками в настройках. В npm start обновления отключены. Обновление никогда не перезапускает Nova во время игры или операций с файлами.

В .github/workflows/release.yml настроена автоматическая сборка Windows x64, Linux x64 и macOS arm64/x64 при каждом push в main. Готовые установщики доступны в Actions → Build Nova → завершённый запуск → Artifacts (14 дней). Загрузите исходники вместе с package-lock.json и .github в корень репозитория. node_modules, dist и игровые данные не загружайте. Для выпуска:

1. Измените version в package.json и package-lock.json (npm version 1.0.1 --no-git-tag-version).
2. Сохраните изменения коммитом и загрузите их в GitHub.
3. Создайте тег той же версии v1.0.1 и отправьте его в GitHub.
4. Actions соберёт установщики и метаданные latest.yml / latest-mac.yml / latest-linux.yml в Releases. Для первого обновления сначала установите текущую новую сборку вручную.

workflow_dispatch собирает артефакты без публикации. Секрет GITHUB_TOKEN выдаётся Actions автоматически. Репозиторий и Releases должны быть доступны пользователям; приватный репозиторий нельзя обновлять этим публичным URL без отдельной авторизации. Токен GitHub не встраивается в приложение.

Для автообновлений macOS необходима подпись Developer ID. Настройте секреты CSC_LINK (сертификат p12 в base64), CSC_KEY_PASSWORD, APPLE_ID, APPLE_APP_SPECIFIC_PASSWORD, APPLE_TEAM_ID для подписи/notarization. Без сертификата macOS-сборку можно установить вручную, но автообновление macOS нельзя считать рабочим. Для Windows рекомендуется сертификат подписи; Linux использует AppImage. Адрес generic-сервера можно переопределить в настройках, сохраняя HTTPS.

Git-репозиторий проекта: https://github.com/Kovtyndumas/NovaLauncher. Публикация установщиков запускается отправкой тега версии; загрузка исходников в main автоматически собирает артефакты без создания релиза.

Начиная с 1.0.1 CI проверяет codesign --verify --deep --strict и запускает собранную Nova.app в изолированном тестовом профиле. Публикация Releases выполняется отдельным заданием только после всех проверок, через черновик релиза. Для полноценного прохождения Gatekeeper без ручного разрешения по-прежнему нужны Developer ID и notarization.

Открытие Nova (1.0.2): первое приветствие показывается новым пользователям один раз, затем используется короткая анимация. Пропуск — кнопкой или Escape / Enter / пробелом. «Настройки → Лаунчер → Первое открытие → Посмотреть» повторяет вступление, сохраняя инстансы и аккаунт. Анимации можно отключить; системное уменьшение движения учитывается автоматически. Окно появляется только после первого готового кадра.
